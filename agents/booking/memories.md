# Booking memories

Commits and PR numbers refer to this repository (github.com/mrpia/mega-dev-s04-rentaplace). Seeded 2026-11-18.

## Internal engineering

- In `createBooking`, keep the idempotency-key replay ahead of `assertAvailable`. A retry with the same key, guest, home, dates and guest count must return the stored reservation with `replayed: true` and no second booking or payout; a retry that differs in any of those fails with 409 `REQUEST_CONFLICT`. [374848f, 860dbd9, 56c59df]
- Put a new check that refuses a checkout inside the transaction after that replay, as PR #1 does with `assertBookable`, so a retry of a reservation made before the change still returns it. [d74d179, PR #1]
- The three-night minimum follows that rule: `createBooking` runs `assertBookable`, then `validateBookableDates` with the past-date check, inside the transaction after the replay, and before the transaction it checks only `validateDates` without the past-date flag. So a retry of a short reservation made before the rule still returns it (a test pins this), and by the code so does a retry whose check-in has since passed (no test pins that). `quote` runs `assertBookable`, then the minimum, then `assertAvailable`. [2026-11-19; b1a74f1, c7c4f71, PR #3]
- `assertAvailable` blocks a stay that overlaps a confirmed, pending or completed reservation or a host block, using `from_date < to AND to_date > from`. So the checkout day is free for the next arrival, pending requests hold their dates, and cancelled or declined reservations free them. [374848f, 860dbd9, 56c59df]
- Checkout writes the reservation, its payout and the confirmation outbox row in one transaction, and a test makes the outbox insert fail and expects no booking and no payout left behind. The confirmation file is written after the commit; a failed write is only logged and leaves the row pending for retry. [374848f, 860dbd9, 56c59df]
- Never store the card number. The checkout test looks for the full demo number in the confirmation file, with and without spaces, and in the returned booking; 7f5d288 changed the file check from a bare "4242" to the full number. [860dbd9, 7f5d288]
- `respondToReservation` builds the reservation it returns by hand, next to its UPDATE, and payout scheduling, the confirmation and the API response all read that object. It must carry the same `payment_status` and `refund_cents` the UPDATE writes; 860dbd9 fixed a version that still carried the request's old values. [860dbd9]
- The strict-cancellation test pins refund 51060 and host payout 40255 to the cent. It reserves on 2026-11-09 and cancels on 2026-11-11, after the free cancellation period, for a stay of 25 November to 2 December 2026. [e61b46a, ccdfb16, b2b4f67]
- Only the owning guest can read or cancel a reservation, and only the listing's host can accept or decline one; anyone else gets 404, not 403. [374848f, 860dbd9]
- Booking dates run on a business date, not the clock: `today()` returns `RAP_TODAY`, or 2026-11-09 when it is unset, and the tests set the same day. The past-date check at checkout and the online-cancel cutoff and refund in `cancelBooking` all use it. [f440195, 374848f, 860dbd9]
- Outside the tests, `createBooking` writes confirmation files into the repo's `outbox/` and log lines into `logs/`, because `OUTBOX_DIR` and `LOG_DIR` fall back to those folders. A script that calls it, even against a scratch database, must set `RAP_OUTBOX_DIR` and `RAP_LOG_DIR` the way `test/setup.ts` does. [f440195, 860dbd9; seen in a conversation, 2026-11-18]
- `cancelBooking` takes the refunded accommodation from `refundBreakdown` in cancellation.ts instead of guessing it from the refund amount. The host is paid the kept accommodation plus the holiday surcharge, less 3%, and nothing after a full refund. [2026-11-19; b2b4f67, PR #2]

## Customer facing

- A full refund cancels the host's scheduled payout; a partial refund keeps the host's share of the retained accommodation and holiday surcharge scheduled, after the platform fee, and marks the payment `partially_refunded`. Before e61b46a every cancellation cancelled the payout and marked the payment refunded. [e61b46a, b2b4f67]
- A checkout is confirmed at once only when the home has instant book and the `instant_booking` flag is on. Otherwise it is a pending request with the payment authorized and no payout until the host accepts; a decline releases the payment, refunds the full total and frees the dates. [374848f, 860dbd9]
- Guests can cancel online only a confirmed or pending reservation whose check-in is today or later; after that the app sends them to support. Cancelling a pending request refunds the full total whatever the policy, and cancelling twice returns the first cancellation unchanged. [374848f, 860dbd9]
- Paused and closed homes take no new quotes or reservations (409 `LISTING_NOT_BOOKABLE`), and their page stays reachable for guests with a trip there. [decided in a conversation, 2026-11-18; PR #1, d74d179]
- When a home is paused or closed, its existing reservations stay as they are: payouts stay scheduled, guests can cancel, and hosts can still accept or decline pending requests. Closing must not cancel them, because hosts have no way to cancel a confirmed stay and the cancellation would happen without anyone choosing it. [decided in a conversation, 2026-11-18; PR #1, d74d179]
- New quotes and reservations need at least three nights, on every home and date, and hosts can't set their own minimum. Reservations made before the rule keep their dates, and guests can still see, cancel and retry them. [decided in a conversation, 2026-11-19; b1a74f1, PR #3]
- Every new reservation can be cancelled for a full refund, service fee included and whatever the policy, on the day it is made and the next business date. The period is counted in business dates, not hours. [2026-11-19; b2b4f67, PR #2]
- A stay with at least one holiday night gets a full refund when cancelled at least the host's refund days before check-in, or the policy refund if that is more, so the window can only add to a refund. Pending requests still get their full total back. [2026-11-19; b2b4f67, PR #2]
- A partial refund never returns the holiday surcharge or the tax on it. If a holiday-stay refund is ever zero, the host gets the accommodation and surcharge less 3%, without the cleaning fee. [2026-11-19; b2b4f67, PR #2]
