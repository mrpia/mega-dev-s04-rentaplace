# Booking glossary

Terms that mean something specific inside the Booking area (`src/domain/bookings.ts` and `test/bookings.test.ts`), each with what it guarantees. Commits and PR numbers refer to this repository (github.com/mrpia/mega-dev-s04-rentaplace). Written 2026-11-19 from the code and tests on main (72a41c1) and `memories.md`; where the code used a word two ways, the owner chose the meaning in a conversation that day.

- **Bookable**: a home whose listing status is `active`; `assertBookable` refuses a paused or closed one with 409 `LISTING_NOT_BOOKABLE`. It guarantees that no new quote or reservation is made for such a home and says nothing about dates: despite its name, `validateBookableDates` checks the minimum stay, not the home. [d74d179, PR #1; decided in a conversation, 2026-11-19]
- **Available**: no confirmed, pending or completed reservation and no host block overlaps the stay (`from_date < to AND to_date > from`, in `assertAvailable`). It guarantees that two held stays never share a night of one listing, while the checkout day stays free for the next arrival. [374848f, 860dbd9, 56c59df]
- **Minimum stay**: three nights for every new reservation, checked in `quote` and, inside the checkout transaction, after the replay. It guarantees that no new reservation is shorter, while reservations made before the rule can still be read, cancelled and replayed. [b1a74f1, PR #3; decided in a conversation, 2026-11-19]
- **Replay**: a checkout whose request key (`idempotencyKey`, stored as `idempotency_key`) is already on a reservation returns that reservation with `replayed: true`, ahead of the bookable, minimum-stay and availability checks. It guarantees no second reservation, payout or confirmation for one key, even after the home closed or the rules changed; a retry that differs in guest, home, dates or guest count gets 409 `REQUEST_CONFLICT`. [374848f, 860dbd9, 56c59df, d74d179, b1a74f1]
- **Pending**: only the reservation status, for a request on a home without instant book (or with the `instant_booking` flag off) that waits for its host. It guarantees that the dates are held, the payment is only authorized and no payout exists until the host accepts. [374848f, 860dbd9; decided in a conversation, 2026-11-19]
- **Confirmation**: the message `queueConfirmation` puts in `email_outbox` for every new reservation and every accept or decline, carrying the reservation's status at that moment; it does not mean the reservation is confirmed. It guarantees that the message is inserted in the same transaction as the reservation or status change (a failed insert rolls both back) and never contains the card number. [374848f, 860dbd9, 56c59df, 7f5d288; decided in a conversation, 2026-11-19]
- **Unwritten confirmation**: an `email_outbox` row (status `pending` in the table) whose file `flushOutbox` has not yet written to `OUTBOX_DIR`. It guarantees a retry on the next flush, because a failed write is only logged and leaves the row as it is. [374848f, 860dbd9, 56c59df; decided in a conversation, 2026-11-19]
- **Business date**: `today()`, which reads `RAP_TODAY` (2026-11-09 when unset), never the wall clock. It guarantees that the past-date check, the free cancellation period (`free_cancel_until`, the business date after the day of reserving) and the online-cancel cutoff only move when `RAP_TODAY` does. [f440195, 374848f, 860dbd9, b2b4f67]
- **Refund**: charged money going back to the guest, with `payment_status` `refunded` or `partially_refunded`; ending a pending request only releases an authorization, so it is not a refund, though the code writes the total into `refund_cents` either way and marks a guest's cancel of a pending request `refunded` (a host decline is marked `released`). A full refund cancels the scheduled payout and a partial one keeps the host's share scheduled. [e61b46a, b2b4f67, 374848f, 860dbd9; decided in a conversation, 2026-11-19]
- **Payout**: the one `payouts` row of a confirmed reservation (`payout-<booking id>`), scheduled for the day after check-in at the reservation's `host_payout_cents`, written in the same transaction as the checkout or the host's acceptance. A cancellation rewrites its amount to the kept accommodation and holiday surcharge less 3%, or cancels it after a full refund. [374848f, 860dbd9, e61b46a, b2b4f67]
